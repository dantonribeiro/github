capítulo 01 · base

O que você
precisa saber.

Git é local e distribuído. GitHub hospeda repositórios e cria uma camada de colaboração.

LOCAL01

Git

Sistema de controle de versão que registra commits, permite voltar no tempo e desenvolver em paralelo.

REMOTO02

GitHub

Plataforma para hospedar projetos Git, revisar código, acompanhar tarefas e automatizar entregas.

capítulo 02 · ciclo diário

Da mudança
ao commit.

O fluxo separa editar, selecionar, registrar e compartilhar. Cada etapa tem uma intenção.

01 / WORKTREE

Edite

Altere arquivos e experimente no diretório de trabalho.

02 / STAGING

Selecione

Use git add para preparar o próximo registro.

03 / HISTORY

Registre

Crie um commit pequeno e fácil de explicar.

04 / REMOTE

Compartilhe

Envie commits com git push e colabore.

capítulo 05 · prática

Seu primeiro
repositório.

01

Configure

Defina a identidade dos seus commits.

git config --global user.name "Seu nome"
git config --global user.email "voce@email.com"
02

Inicie

Transforme uma pasta em projeto versionado.

mkdir meu-projeto
cd meu-projeto
git init
03

Publique

Conecte o local ao GitHub.

git remote add origin URL
git branch -M main
git push -u origin main

capítulo 06 · além do básico

Quando a história
fica complexa.

git stash

Guarde rascunhos

Salve temporariamente mudanças que ainda não estão prontas para um commit.

git rebase

Reorganize

Reaplique commits sobre uma base atualizada para manter uma linha mais limpa.

git bisect

Investigue

Use busca binária no histórico para encontrar o commit que introduziu um bug.

Desfazer com consciência

git restore
descarta alteração local

git revert HASH
desfaz com novo commit

git reset
reescreve história local

capítulo 07 · disciplina

Antes de
publicar.

Uma boa história também protege o projeto e as pessoas que trabalham nele.

checklist do commit
  • 01Revise git diff --staged.
  • 02Nunca publique tokens, senhas ou `.env`.
  • 03Teste antes de abrir o Pull Request.
  • 04Prefira commits pequenos e mensagens claras.
